A successful future run must preserve signal identity, reject malformed input and retain the previous complete output on failure. No game asset, account, recording or upstream sample is used as probe audio.

The CLI uses the existing direct suspended-creation primitive and a Job with active-process-limit 1 set before creation. The original process/thread/Job objects remain retained through observation and confirmed cleanup. There is no PID lookup. Bounded input arrives over a local first-instance named pipe; a sample/frame-aligned nonempty suffix and EOF stay withheld until genuine positive progress and two equal live module snapshots on that creation handle. App hashes must equal selected candidate bytes; system images must be observed directly under actual SystemDirectory with a finite reviewed name. Unknown origins refuse before content hashing.

The pinned formatter's nine-key progress schema has a cumulative 32 KiB/128-record cap and one 20-second operation budget. `analyzeduration=0` selects FFmpeg defaults, so the recipe deliberately uses positive 100000 microseconds, probesize4096 and explicit PCM/MP3 demuxers. Actual pre-EOF readiness must still be observed; no progress fallback exists. Exit 0, Job-zero, retained-handle exit and confirmed closes are required. Sticky cleanup uncertainty retains the same owner/work files and enters failure hold. An external timeout is containment, not cleanup proof. Supplementary observer/fault calls retain their own Popen and streams on uncertainty and supply no Job or main CLI-origin claim.
