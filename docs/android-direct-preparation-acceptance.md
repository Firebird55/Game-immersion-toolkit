# Direct game preparation acceptance

The Android runtime probe follows **Settings → Check download size →
Download/Update**, including Text only followed by Text + audio. Private-library
onboarding, the Reading chooser and the Stop screen button are retired. Pasting
a viewer link starts capture; clearing it releases the receiver. Browser history
migration is a separate JSON flow under Settings, preserving old recordings.

The acceptance source is generated, never publisher content. An explicit
`toolkitAuthoredGameData` native DEBUG intent selects the separate
`authored-game-data-ui` root. The isolated authored account mode uses this
provider in its own root. Native startup and the Python entry require the native
DEBUG guard. Ordinary startup keeps the real publisher registry. No HTTP switch
installs this provider. Its typed `SourceProof` is an authored contract fixture.

The generated English row and eight-second tone use the ordinary
`GameDataService`, multilingual index, capture session, recording store and
offline source restoration. Exact generated input sizes are quoted before
writing data. Text-only preparation preserves voiced intent without generating
or resolving optional audio. Account and publication fences remain active.

Host validation on November 17, 2026:

- Native-guard/root admission, default-registry isolation, text-only audio
  exclusion, direct preparation, offline restart and deletion with retained
  recordings passed through the real Android HTTP host on Windows.
- The actual compiled shared reader passed Chromium and Firefox at 412 × 915:
  unconnected direct preparation in both modes, capture/favorite/original audio,
  history preview/import/idempotent reimport, reload, optional Lexirise,
  A → B → A isolation, stale requests and explicit corrupt-store recovery.
  Account transport and protected storage were authored host adapters.
- The closed packaged-source test contains 65 owned Python modules. It still
  registers only the two reviewed production discovery/stage providers; the
  acceptance module does not enable another game.

This is source/browser evidence. No APK was built from this cohort. It does not
establish new device/JNI execution, real publisher HTTPS, independent game
preparation or iOS gameplay. The physical decoder candidate in
[shared-core evidence](android-shared-core.md) is an older, separately bound
artifact. A future APK must rerun the corrected probe and retain exact source,
signature, native dependency and result receipts.
