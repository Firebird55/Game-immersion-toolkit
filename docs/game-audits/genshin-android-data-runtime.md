# Genshin direct-data runtime boundary

Status: November 17, 2026. Android must download and update its own publisher
data. This audit describes the remaining local Android execution work; a desktop
preparation/import is not the delivery path.

## Generic interfaces the Android runtime must provide

1. Acquire an immutable publisher object/chunk into an owned cache, verify its
   declared size/digest, and return a range-readable file handle with a lease.
   Record actual transferred and retained bytes, including retries.
2. Decode an authenticated BLB input with a private, provenance-bound numerical
   profile into a bounded seekable body. Enforce current limits, exact block/node
   bounds and original-input identity. A per-bundle temporary-body lifecycle can
   reduce storage only when the runtime actually enforces its eviction contract.
3. Discover the TextMap arithmetic contract from an authenticated executable
   handle. A compatible community description requires separate last-resort
   eligibility evidence. Return private
   typed operands plus all method/input hashes. No fixed revision/RVA is an
   update mechanism.
4. Consume original catalog/object/shard streams into the local generation store,
   resolve aliases, and activate only after all requested locales and bindings
   validate. Failure retains the prior complete generation and its provenance.
5. Decode original media handles to PCM using the same authored dub, interval,
   channel and playback-scope contract. Missing or unknown media never becomes
   confirmed unvoiced. Shared runtime/audio code is a separate reviewed closure.

These interfaces execute on Android. They must not require game installation,
game-code execution, an account login or a desktop compiler.

## Preflight size contract

`genshin_publisher.preflight` reads discovery, official manifests and hotfix
indices. It never calls a native/audio file's `read()` operation. Its
`genshin-official-download-plan-v1` result contains the publisher stamp, selected
locales, deduplicated cache-key ledger and explicit transfer/resident/peak upper
bounds. Sophon objects use declared compressed wire size and decoded cache size;
HTTP hotfix packages use complete declared file size. Shared Mandarin packs are
counted once for simplified/traditional subtitles. Cache reuse is not subtracted
without a separate verified-cache inventory.

The request and result require `content_mode: text | text-audio`. Text planning
does not fetch dub manifests or inspect any PCK inventory and contains no voice
objects; it can quote any official text locale. Text-audio planning contains the
complete selected original dub cache for advance materialization. The common
executor must enforce that mode and verify every required object before marking
text-audio Ready. The older on-demand PC worker result is not that new Ready
contract. Text-only execution must preserve authored bindings/status separately
while suppressing audio retrieval/export triggers; the current legacy worker's
bank-inventory step still needs an execution adapter for that mode.

The native metadata input is a complete publisher object, not an 8 MiB sample.
The current canonical `Native/Data/Metadata/global-metadata.dat` entry is
83,644,132 bytes and owns 65 transport chunks totaling 61,346,746 wire bytes.
The ledger includes every chunk and the full materialized metadata file. The
ManualTextMap container is also included when an authenticated catalog narrows
the plan; it cannot disappear from the quote because it contains no audio.

A caller-owned authenticated catalog for the same publisher narrows selected
locale bundles exactly. Without it, all current design packages form an explicit
upper bound. Only the small catalog/bootstrap stage should precede that
refinement; a new platform adapter must quote its own bootstrap/runtime cost.
The existing PC reader retains decoded bodies, so this plan conservatively uses
the actual per-body guard rather than an invented compression ratio. An Android
adapter can replace that bound only with tested streaming/eviction behavior.

On the retained Global 7.2 metadata, Japanese audio plus Japanese/English text
previously produced 17,559,648,026 wire bytes before original ManualTextMap
metadata/container inputs were included. The updated text-only Japanese/English
quote is 409,594,778 wire bytes after catalog refinement (68 design packages),
including the full metadata ledger. The earlier cold all-design audio bound
was 18,737,067,161 bytes before adding that metadata input. These metadata-only
calculations read zero large
payload bytes. These are not the size of initial on-demand preparation.

The result deliberately has `complete_game_quote: false`. API/manifest fetches,
dispatch-bootstrap parameters, controlled binding archives, Readable/Subtitle
acquisition, publisher movies/film audio, the derived dialogue index, shared
runtime/codecs and historical retained audio are enumerated as
unquoted components. The common game-data layer must quote/merge those required
parts and measure used bytes before presenting a complete per-game size. A
partial sum must not be presented as the whole download or device-storage need.
Deletion must use the common ownership/lease registry for downloaded or derived
objects, preserving study history, account state and calibration.

## Registered original native-input stage

The canonical [Genshin factory](../../backend/genshin_game_data.py) implements the
shared provider contract with explicit context-owned Sophon transport. Its
Windows `GenshinRuntime(layout)` validates the owned portable BLB software and
the pinned static instruction decoder. It never builds, downloads or executes a
managed BLB helper. The normal Windows factory resolves that installed
bundle lazily when the host supplies no explicit runtime. Source-checkout and
incomplete bundle layouts remain unavailable; there is no SDK or PATH fallback.
Android and missing runtimes return an unavailable
reader gate before transferring large game inputs; the instruction decoder alone
does not supply an Android BLB reader.

The first supported stage quotes the official launcher manifest when it exceeds
the metadata allowance, followed by complete original executable and metadata
files. It binds the regional build, language/content selection and runtime
identity, deduplicates complete Sophon chunks, verifies cached bytes before
subtracting them, and authenticates both full materialized files. All transfers
use the shared consent and cancellation context. A stage produces
`PreparationStage`, never a partial dialogue snapshot or text-audio Ready.

With those inputs already verified, a separate local `original-bootstrap-seed`
stage resolves the initial `GlobalVars.dispatchSeed` from the current original
metadata, named static field, initializer, reaching pointer definitions and
original literal table. It pins no current address, field index, offset or value.
The quote is zero transfer and a bounded receipt allocation, not a whole-game
download quote. Whole publisher length/MD5 and complete content hashes are
checked again before extraction; ambiguous stores, clobbers and changed owners
fail without replacing the prior stage or accepted library. The private receipt
binds full input identities, verified runtime and maintained parser code. A
restart rechecks these inputs and the complete receipt hash from the matching
regional build/language/content stage handle; handles contain no seed value.
An invalid or unreceipted cache requires original extraction again, never a
community key-cache fallback. The same original-only extraction now follows the
typed `Miscs.GetConfigChannel` cache and `LoadChannelConfigBlk` consumer. The
current `GlobalVars.channelConfigBlkName` field supplies the basename; the
loader supplies bounded object-ID candidates through its actual paired
size/read argument flow. Neither the basename nor an object ID is fixed in the
toolkit.

The following `original-channel-profile` stage quotes the whole publisher file
and all missing complete transport chunks before fetching it. It reuses the
same context-owned Sophon cache, whole size/MD5 checks and verified installed
software. All full codec contracts are derived from the current original native
input. Every candidate is checked against the complete original named-object
map, all referenced data-object lengths/padding, the native-owned object IDs and
strict UTF-8/JSON profile shape. Exactly one complete result is required;
ambiguity, missing source/method/recipe identity or malformed extra map entries
fail without replacing the prior stage or library. No saved analyst parameters
or community numeric descriptions are inputs.

The bounded disk upper estimate includes the materialized source, expanded
transport cache, sequential decoder scratch and private parameter/receipt data.
The private receipt binds the source, current original inputs, helper, parser
code and codec method hashes. Restart checks its full hash from the matching
accepted stage handle, reauthenticates the source and parses the preserved
payload again. A failed attempt reuses verified source chunks after a new size
check. Both text modes remain `PreparationStage`; this stage fetches no audio.

The ordinary Windows profile route now uses the owned standard-library Python
BLB3 transformation. It does not resolve, build or execute a managed helper or
consult a .NET SDK. The prior C# helper remains a differential oracle for this
route. Two authored parameter profiles match its complete output byte for byte;
one retained publisher-authenticated profile also matches the prior decoded
container, decompressed body, full named-object map and strict typed profile.
That retained-input comparison does not prove fresh parameter acquisition.

The portable helper's identity binds its complete loader-provided code object,
concordance with the functions actually loaded, and its format/bounds contract.
It excludes installation paths and private parameter values. Missing, corrupt
or stale software evidence fails without a managed fallback. Software changes
invalidate affected stage receipts; earlier source files and the accepted
dialogue library remain retained. The installed-bundle and verified native x64
decoder gate still precedes large publisher downloads. This Windows integration
does not enable the Android factory or establish APK runtime delivery.

Profile preparation now unpacks the decoded body through a standard-library
module with explicit package and output limits. It shares the bounded raw LZ4
decoder with the Witcher reader. The profile receipt fingerprints both modules,
and the desktop original-text body cache includes their code digests. Existing
source downloads and accepted libraries are retained.

The standalone Android profile adapter loads independently of the game-data
factory and accepts the decoder instance already installed by the Android host
from its verified FrameOcr provider. Its profile
receipt binds APK-entry and license verification, ABI, native source, library
and manifest digests, the 15-case decoder contract, and the portable codec and
reader implementation. This evidence attests the decoder entry in the installed
APK. The ordinary Android provider remains gated pending device validation of
the full profile path and the remaining original source stages.

This acceptance is expressly **profile only**. Its receipt marks full catalog,
selected-shard, response-signature and override acceptance false. Final original
Source activation must still validate its complete catalog and selected text
shards. A cached profile never becomes an active descriptor or a partial
dialogue library.

The following plan remains unavailable at the original content reader. Original
RSA operation, key role and parameter-source ownership, complete
request-value/response routing, response-signature verification and possible
IFix or other later overrides remain open. The toolkit adapter's private RSA
decrypt contract does not prove the original client uses private parameters.
The inspected original transport is synchronous `UnityEngine.WWW`; the
successful body/error branch enters a protected continuation without a proved
content-recovery or signature operation. Separate `content` and `sign` fields
could have distinct roles, but public-key verification/recovery is also
unproved. No additional parameter owner follows from the saved typed
declarations. See the [response evidence matrix](genshin.md) for these limits.
The inspected `UseDispatchData` body reads six configuration fields and does not
write the seed, which does not exclude other replacement paths. The other
original dialogue bindings, Subtitle
acquisition, selected-dub materialization and full ordinary update acceptance
still need their complete source route. The accepted dialogue library remains
available as the original-source work continues.
