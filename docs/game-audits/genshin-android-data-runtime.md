# Genshin direct-data runtime boundary

Status: November 17, 2026. Android must download and update its own publisher
data. This audit describes the remaining local Android execution work; a desktop
preparation/import is not the delivery path.

## Current PC checkpoint

The explicit original TextMap source completed the ordinary Japanese/English
worker against retained, authenticated publisher metadata and the matching
immutable helper commit. All 480,619 complete records match the previous working
index, including text, translations, voice references and predecessor context.
Normal playback of both previously reviewed Japanese recordings produced the
same PCM hashes offline. The source receipt survived ordinary worker publication
and offline index reopen. No new game bytes or network requests were required
for that replay; it does not claim a fresh online discovery or an old-to-new
original-content replay.

All fifteen original locale sets were independently replayed: 15,360 shards,
495 publisher packages and 12,779,262 rows. The exact immutable LF software was
then used to decode all 495 packages again; every body hash matched. A closed
Windows x64 apphost with 202 resources and 81,820,487 bytes validated against its
source/runtime receipts and decoded an original package without consulting a
host SDK. This proves that helper contract, not full native application delivery.

The normal provider remains unchanged. Original Readable/Subtitle acquisition,
complete update/retention acceptance and the Android runtime remain open. The
new receipt labels the existing Readable and Subtitle text routes separately;
they must obtain publisher bytes before all text can be called publisher-sourced.
The latest acceptance rule also requires independent parameter recovery from
available official files first. Current BLB and dispatch bootstrap still depend
on community descriptions; no impossibility evidence establishes their
eligibility as a last resort. Source pinning and successful payload decoding do
not close that official-derivation gap or establish present source maintenance.

`genshin_native_x64.decoder()` has an explicit Windows-amd64 Capstone/DLL
contract. That experimental full-native Talk/Voice ownership route is not
used by the current original TextMap preparation path: `Image` and the
bounded TextMap instruction matcher operate on data. Do not add an Android
Capstone dependency solely because the module also contains that separate API.

The current input is the publisher's canonical Windows data, downloaded directly
by the client. Its executable is parsed, never run. No Android runtime or
physical-device compatibility is established by the PC data replay.

A bounded follow-up found all five game-specific BLB arrays as literal data in
the authenticated original executable. The other four arrays match standard
Rijndael/GF constructions. Eight validated RIP-relative references belong to
three small native consumers. This is a diagnostic ownership lead, not yet an
autonomous parameter resolver: the search used a retained profile as an initial
seed. It positively identifies available official material and does not support
an impossibility claim. No original arrays are included in the public source.

## Generic interfaces the Android runtime must provide

1. Acquire an immutable publisher object/chunk into an owned cache, verify its
   declared size/digest, and return a range-readable file handle with a lease.
   Record actual transferred and retained bytes, including retries.
2. Decode an authenticated BLB input with a private, provenance-bound numerical
   profile into a bounded seekable body. Enforce current limits, exact block/node
   bounds and original-input identity. A per-bundle temporary-body lifecycle can
   reduce storage only when the runtime actually enforces its eviction contract.
3. Discover the TextMap arithmetic contract from an authenticated executable
   handle. A compatible community description requires separate last-resort
   eligibility evidence. Return private
   typed operands plus all method/input hashes. No fixed revision/RVA is an
   update mechanism.
4. Consume original catalog/object/shard streams into the local generation store,
   resolve aliases, and activate only after all requested locales and bindings
   validate. Failure retains the prior complete generation and its provenance.
5. Decode original media handles to PCM using the same authored dub, interval,
   channel and playback-scope contract. Missing or unknown media never becomes
   confirmed unvoiced. Shared runtime/audio code is a separate reviewed closure.

These interfaces execute on Android. They must not require game installation,
game-code execution, an account login or a desktop compiler.

## Preflight size contract

`genshin_publisher.preflight` reads discovery, official manifests and hotfix
indices. It never calls a native/audio file's `read()` operation. Its
`genshin-official-download-plan-v1` result contains the publisher stamp, selected
locales, deduplicated cache-key ledger and explicit transfer/resident/peak upper
bounds. Sophon objects use declared compressed wire size and decoded cache size;
HTTP hotfix packages use complete declared file size. Shared Mandarin packs are
counted once for simplified/traditional subtitles. Cache reuse is not subtracted
without a separate verified-cache inventory.

A caller-owned authenticated catalog for the same publisher narrows selected
locale bundles exactly. Without it, all current design packages form an explicit
upper bound. Only the small catalog/bootstrap stage should precede that
refinement; a new platform adapter must quote its own bootstrap/runtime cost.
The existing PC reader retains decoded bodies, so this plan conservatively uses
the actual per-body guard rather than an invented compression ratio. An Android
adapter can replace that bound only with tested streaming/eviction behavior.

On the retained Global 7.2 metadata, Japanese audio plus Japanese/English text
produced 17,559,648,026 wire bytes as the **complete selected-dub PCK cache** upper
bound after catalog refinement (67 design packages). The cold all-design bound
was 18,737,067,161 bytes (533 design packages). Both calculations read zero large
payload bytes. These are not the size of initial on-demand preparation.

The result deliberately has `complete_game_quote: false`. API/manifest fetches,
bootstrap/codec-parameter inputs, controlled binding archives, Readable/Subtitle
acquisition, publisher movies/film audio, the derived dialogue index, shared
runtime/codecs and historical retained audio are enumerated as
unquoted components. The common game-data layer must quote/merge those required
parts and measure used bytes before presenting a complete per-game size. A
partial sum must not be presented as the whole download or device-storage need.
Deletion must use the common ownership/lease registry for downloaded or derived
objects, preserving study history, account state and calibration.
