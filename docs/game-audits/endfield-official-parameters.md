# Endfield official parameters and independent preparation

Checkpoint: November 17, 2026. This report concerns the common VFS key,
directory map and Lua XXTEA key. It does not resolve the separately retained prologue audio
exception or claim that every other cryptographic master is now native-derived.

## Implemented PC route

The ordinary installation-free path now retains the publisher client's identity
alongside the selected resource layers. `endfield_release.latest_client` and
`discover` read the regional launcher declaration: version, region, immutable
client file URL, declared game-file manifest MD5 and original package URL/MD5/size
tuples. Temporary package query tokens are discarded. A changed artifact digest
therefore changes the client identity even if its file URL is unchanged.

The original public launcher endpoints are
[Global](https://launcher.gryphline.com/api/game/get_latest) and
[mainland China](https://launcher.hypergryph.com/api/game/get_latest). Their
selected `pkg.file_path` owns `GameAssembly.dll` and
`Endfield_Data/il2cpp_data/Metadata/global-metadata.dat`; the toolkit does not
choose a native file from a game installation or a newer community extraction.

The static reader resolves IL2CPP29 images, types, fields, tokens, literal usages
and codegen registrations. It locates `VirtualFileSystem` and `VFSDefine` by
original metadata identities, verifies their static field types/offsets and uses
original PE sections and chained unwind ownership for bounded x64 reads. No
revision addresses, current key literals or manually maintained directory IDs
are distributed. No game library executes, and no native emulation is used.

The recognized common-key path follows the original fragment-array order,
delimiter and actual caller mask. Metadata binds the conversion calls to
`System.Convert.TryFromBase64Chars` and `System.Text.Encoding.get_UTF8`; owned
instructions establish the subtract-byte/modulo operation. The directory path
follows the original enum-to-string map, UTF-8 conversion, metadata-resolved
`Unity.Collections.xxHash3.Hash64`, the low/high-word fold and original
little-endian uppercase-hex formatter. An unknown contract is an explicit
preparation failure; it does not select a guessed key or directory.

`endfield_release.group` supplies these parameters to ordinary tables, Lua,
bundle indexes and voice packages. Film-event resolution, streamed original
recordings and source-derived world/SNS controls use the same release-bound
key. Every actually requested original index must pass its normal CRC and
complete typed-schema checks. Before publishing a new parameter/index witness,
the reader rechecks the original launcher artifact declaration. Already verified
identical cached indexes remain available offline. Client identities, previous
descriptors, recordings and working data are not overwritten by another client's
failed preparation.

The client-range receipt proves exact HTTPS endpoint, byte bounds, declared
length and a local SHA-256. It **does not** prove a complete DLL/metadata-file or
package hash from those partial ranges. The launcher artifact hashes remain in
the identity, and independent original VFS CRC/schema controls are required.
Those two evidence levels must remain distinct.

The Lua source route now resolves the original `Beyond.Lua.LuaCypher` owner,
its typed `KEYS` array, constructor assignments and `GetKey` caller. Concrete
metadata `MethodSpec` arguments bind the five-string formatting call; local
operand definitions bind its current array elements and complete delimiter.
The same owned subtract/modulo converter supplies the decoded 16-byte UTF-8
key. The reader contains no current fragment values, key literals, method
indices or revision addresses. Unknown formatting, argument ownership/types,
field definitions or conversion contracts fail explicitly. This is bounded
static recognition, without running original instructions or native callbacks.

World-dialogue, Baker and training source preparation all use this release-owned
Lua route. Before activation, the selected Lua index must already have passed
the common-key CRC/typed checks. Each complete source file must pass its original
VFS-declared MD5, XXTEA length/UTF-8 decode and source control. The activation
boundary independently repeats the decode and rechecks the original launcher
identity. Private witnesses bind the original file MD5, decrypted SHA-256 and
selected index SHA-256 to that client. An identical validated witness works
offline; an invalid candidate or changed client cannot replace it. Existing UI
ownership validators still decide whether those source files support capture.

Cold source preflight and extraction first check the reviewed native runtime,
before requesting even native-file headers. An unsupported host or missing
Capstone/XXH3 closure produces `missing_toolkit_runtime` with an Endfield-specific
action; it is not classified as a game-format change. The current closure is
Windows amd64/Python 3.12 only. Existing validated parameter witnesses and older
prepared data remain readable without a fresh native extraction. This gate does
not introduce a community fallback or implement Linux, macOS or Android closure.

Modern plain index acquisition now carries only the original common key,
directory map and protocol in `IndexParameters`. Table, Lua and UI indexes can
be read without fetching AKPK seed documents or voice package indexes; outer
payload reads also need only those common fields. A bank or media decoder given
index-only parameters returns `missing_original_audio_master` before reading
audio, with previous data retained. There are no zero multiplier/XOR substitutes.
The NumPy audio mask dependency is loaded only by actual audio transformation.
Old immutable descriptors keep their exact frozen parameter provenance. Complete
text-only production and original timeline/UI-bundle AES sourcing remain
separate open gates.

### Implemented native-source prerequisites — November 17

The bounded `endfield_client_archive.Archive` reader consumes the launcher's
declared split artifacts through an injected range reader. It validates ZIP64
terminal/directory ownership, unique member names, nonoverlapping member bounds,
the selected local header, bounded Deflate output and the complete member CRC.
These controls do not claim a whole-part MD5 or the still-undecoded GameFiles
per-member hash. No game library is loaded or executed.

`endfield_native_import.managed_import` derives the current module and entrypoint
from the metadata-owned two-argument Wwise wrapper, PInvoke flags, lazy dispatch
slot and original static StringView descriptor. `NativeImage` resolves that
exact current export, its bounded direct wrappers and chained-unwind-owned
continuations. Neither a version address nor a generated export-name list is a
product input. Authored changing-name/address fixtures cover the positive path;
changed ABI, ownership, branches, forwarders and cycles fail closed.

`endfield_publisher_signature.verify` is an explicit Windows capability. It
locks the original data file against writes/deletion, rejects a final reparse
point and uses only Windows system WinTrust/Crypt32 software to require a trusted
offline Authenticode signature by the publisher. It does not claim fresh online
revocation checks or Android/Linux/macOS signature support. An unsigned authored
PE fails the actual Windows API check. Existing prepared data is retained when
the verifier capability is unavailable.

A zero-network replay of the new readers derives the real 1.6.4 import, reads
all 1,782 cached original directory entries, selects the same native member and
revalidates its complete 3,587,464-byte output CRC and publisher signature. The
compressed native payload was not retained, so the acquisition-time Deflate
check is not claimed as newly replayed. The selected transform has three
chained spans totaling 682 bytes and 183 instructions; its earlier 135-byte
record was only the primary span, not the complete function. All twelve
multiply occurrences and three initial-XOR occurrences agree across its
complete owned paths. Values remain private. This prerequisite checkpoint does
not yet activate a production AKPK master. Other timeline/AES masters remain open.

The subsequent `endfield_akpk_contract.derive` candidate recognizer follows the
current export's original output-pointer contract into the package loader,
binds the standard/custom package magic to its single flag assignment and the

`endfield_akpk_controls.validate` requires a complete original VFS file MD5 and

## Android portability audit

The first `endfield_game_data.create_provider` integration is a bounded client-
metadata bootstrap, not a completed content provider. Through the shared
context-owned publisher transport it reads only the launcher declaration and
4,352 original header bytes during planning. Exact PE/IL2CPP table ranges and
their publisher-response owner lengths determine the subsequent download and
disk estimate. The quoted transfer is an explicit upper bound: table bytes plus
4,198,656 bytes for two bounded launcher rechecks and the repeated 4,352-byte
headers. All actual verification metadata, assets and audio share the approved
download budget; the table-only total is not sufficient. Tests with the real
shared preparation context and publisher transport exercise growing unrelated
launcher fields in both content modes. Download rechecks the entire plan and client declaration, uses
only pinned-owner ranges and returns `PreparationStage`; it never returns
`SnapshotSource`, a voice source or a publisher-content proof. Another original
parameter/index verification and selected-content estimate is still needed.

Both `text` and `text-audio` selections bind the request identity and transfer
zero audio in this stage. These necessary shared client tables are stated
metadata overhead, not a text-only audio download. A changed mode, client,
range, stage or estimate stops before large transfer. An interrupted stage
does not replace an existing library. The source-stage revision binds the
original client artifact generation independently of content mode; the request,
plan handle and private cache identity separately bind mode and complete locale
selection, keeping the corresponding receipts separate.
Renewed temporary launcher tokens or unrelated response fields do not create a
new generation or invalidate an otherwise identical approved plan; canonical
artifact declarations, original header SHA-256 values, ranges and sizes remain
strict recheck inputs.
Independent Android/Linux/macOS runtime
closure remains unsupported by this initial adapter and fails before source
I/O; supplying an unreviewed native object does not bypass that gate.

The shared Android engine is native CPython 3.12.15 through Chaquopy 17.2.0,
targeting arm64-v8a and x86_64. It is not a browser/WASM interpreter. The current
prepared-capture module set contains the pure presentation helpers, not the full
official Endfield producer. The owner-authorized endpoint is independent
official download/update on Android and PC; importing a PC-prepared library is
not completion of that endpoint.

## Download and storage preflight

`endfield_parameters.preflight_client(tools, identity)` is a producer-facing
preflight. It reads at most 256 metadata-header bytes and 4,096 PE-header bytes
before any large client-table request. For the frozen 1.6.4 source it reports
106,097,620 bytes of required tables/static sections plus a bounded 331,776-byte
allowance for owned code, field records and boundary probes. An already validated
client reports zero new parameter-table bytes. These are parameter-stage figures,
not the size of the whole game or the complete selected dialogue library.

The complete flow needs two explicit planning stages:

1. Obtain the small official launcher/header declarations and show the cold
   parameter-metadata estimate, existing verified cache and staging allowance.
   Do not hide the roughly 101-MiB cold metadata step behind a precise-looking
   audio total. The preflight itself does not fetch those large bodies.
2. After the required original indexes are available and validated, resolve the
   selected region/dub/story dependency closure. Use each VFS file's original
   chunk identity, offset, size and digest; use bounded package headers for bank
   directories and media offsets. Deduplicate and merge overlapping ranges of
   the same immutable object. Account separately for required tables, UI/cue
   assets, original WEM/soundtrack ranges, decoded playback output and temporary
   staging. Subtract only size-and-digest-verified cached content.

Unknown manifest entries, unresolved media bindings or unknown decoded-output
sizes remain unknown amounts or conservative labeled bounds. They must not be
reported as zero, as the full launcher package, or as a completed download plan.
The shared game-data owner still needs to consume this preflight and implement
the selected-content ledger, cancellation/recovery and Android/PC Download/Delete
controls. No claim is made that those controls are delivered by this reader.

Used storage should count actual owned files and staged work, including indexes,
source receipts, decoded playback caches and partial downloads. Deletion must be
scoped to the selected game's owned cache roots; shared fixed software and user
recordings need their own ownership/retention rules. Previous usable generations
remain intact until the new checked generation is activated.
