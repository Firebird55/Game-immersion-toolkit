# Native Unreal reader failure observation

The build-host [probe](../scripts/probe-native-unreal.py) uses the actual app-local NTE/Wuwa bridge against authored, unencrypted compressed archives. It does not access real game files, recordings, accounts or archive keys. Its existing success schema remains `toolkit-unreal-native-probe-v1`, with the same seven checks and existing native acceptance predicates.

[Run41327579185](https://github.com/Firebird55/Game-immersion-toolkit/actions/runs/41327579185), attempt2, exact source `eb27e74e084dde6f4b2dab0a7b486838a8bcb781`, failed Windows job124918410553 at the shared self-contained archive-reader step. Image windows-2025-vs2026/20261030.294.1 emitted only the historical v1 `passed:false`, `native-reader-probe-failed` result. No compiler code or particular reader/IO/cleanup cause was established. Do not relabel that historical observation as v2.

Failure-only `toolkit-unreal-native-probe-failure-v2` adds closed stage and authored-operation labels, a sticky first failure kind, the actual completed prefix of the seven existing checks, and separate child-result/cleanup context. Source, resource, immutable-copy, helper-receipt, runtime-resolution, fixture and each authored operation have fixed labels. Initial state is `not-observed`; fixture creation and successful-path fixture removal have their own labels. A throwing constructor does not establish that no underlying process was created and permits no replacement owner or PID adoption.

Child context contains only fixed return categories (not-observed, zero, one, three, other-nonzero), output presence/over-limit states and exact known reply labels. It publishes no path, command, request, exception text/type/stack, environment, raw stdout/stderr, arbitrary code, output length/hash, PID or private receipt identity. A child exit1 alone does not prove that the managed reader ran. The managed entry suppresses supplier output; Python cannot recover an underlying supplier exception from its fixed failure reply.

The original 60-second communicate timeout and subsequent 8192-byte checks remain unchanged. Those checks occur after capture and are not a streaming memory bound. Neither an observed reply nor diagnostics can substitute for archive membership, exact authored bytes, app-local runtime identity, rejection or immutable-input checks. Existing requests, archive bytes, commands, environment, SDK, managed entry and supplier/component manifests stay unchanged.

The first body exception remains privately retained even when stop or stream-close also fails. Stop is attempted once on the actual returned owner; only its confirmed return permits one stream-close attempt. A failed stop leaves streams untouched: a reader left by communicate's timeout may still hold a buffered stream lock. Cleanup is confirmed only when both calls return. Uncertainty retains the actual owner/error objects and authored fixture, without removal, query or retry. Constructor failure has no returned owner to clean up; it is explicitly unconfirmed. Failed probes retain their marked fixture, so this is not a full application cleanup proof. Success still removes its temporary fixture; failed removal cannot publish a passing result.

Portable tests cover source/receipt/fixture boundaries, known output checks, strict projection relations, private canaries and retained original objects with owned process doubles. An actual anonymous-pipe/BufferedReader test proves the first refusal returns while its reader still holds the lock; only the test then releases its own writer FD, joins the reader and closes the read side. This is authored IO evidence, not actual apphost, Windows ABI, game/codec, encrypted archive, Oodle, cleanup, rights, Windows11, physical/global ownership, keeper-loss, warm-routing or R19 acceptance. It establishes no cause for the historical eb27 failure. A new exact-head Windows observation is pending. No installer or release is included.
