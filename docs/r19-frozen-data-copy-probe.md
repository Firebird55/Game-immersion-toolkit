existing frozen frontend/API process owner. It exercises one authored Chinese
transcript and favorite write. It does not enable production migration or an
installer. Its first frozen Windows execution at `ed153ab` passed; the downloaded
source-bound receipt was independently reviewed. This closes only the fixed
authored-copy observation described below.

The existing [completion plan](r19-completion-plan.md) C2/C3/C4 gates remain
open. The successful historical owned-host, cold-slot and
[living keeper](r19-frozen-keeper-probe.md) experiments remain separate evidence.

## Ownership and copy order

`SyntheticHostCoordinator` is the sole owner of both actual FileShare.None
leases: authored `legacy/data/companion-operation.lock` and separate private
target `host-v1/migration-runtime.lock`. `FrozenProbeHost` owns the fixed
frontend/API Job and creation records; it acquires no data lease. The keeper
wrapper, source updater and its nested lock are not invoked.

The fixed `authored-data-copy` stdin case is available only through the existing
quarantined runtime-experiment host probe. There is no new CLI target, arbitrary
command/root input or browser ownership flag. The normal C1/bootstrap and
production/source paths retain their existing behavior.

1. Create fresh marked temporary source/target roots beneath the actual child
   TEMP. Derive a checked RuntimeLayout with its real data root at source/data.
   Acquire coordinator exclusion, save the initial fixture pointer bytes and
   seed two rows through actual `TranscriptStore.add` and `TextMatch`.
2. Explicitly close every setup SQLite connection, including the constructor's
   initialization connection. The setup-only tracking subclass changes no
   production SQL or storage behavior. No parent source DB connection remains
   while a child writes or while the copy runs.
3. Register both real frozen writers suspended, detached and in their Job before
   resume. Await readiness tied to their actual retained creation objects and
   listeners; send the real favorite PATCH through the same identity scope.
   The API probe mocks external game/account/OCR/update side effects; Runtime,
   SQLite, favorite route and writer handoff are real.
4. Enter the existing stopped_writers operation. Perform actual opt-in strict C2
   POST, require running=false, ordinary status 503 and healthy control. The API
   owns its existing total 30-second drain deadline; HTTP allows 35 seconds.
   Process exit and file copying have separate bounded phases.
5. Close admission and confirm each actual retained writer process object
   signaled, the registered Job empty and native cleanup complete. Only then
   return a complete WriterStopProof and let the coordinator mint its typed
   barrier. Readiness, terminal threads or empty Job accounting alone are not
   that proof. Unknown members/helpers remain refusals.
6. Run `copy_and_verify_synthetic` under serialization and both continuously held
   leases. Require verified copy, source inventory preservation and no target
   activation. Check current schema/rows from a separate read-only verification
   copy of each SQLite/WAL/SHM set; check original snapshot hashes afterward.
7. Successful stopped_writers exit restarts a fresh **source** cohort/Job with a
   new generation and genuine creation records. The old barrier must refuse.
   Check Chinese/context/favorite state through the new owned API and the
   fixture pointer against its initial bytes. No target process, route change,
   runtime activate call, capture start or warm-index claim occurs.
8. Strictly drain/confirm the fresh cohort stopped, explicitly close coordinator
   leases, verify source entry and canonical ports available, then remove
   successful private fixture state before publishing a passing receipt.

Source byte preservation is checked before the fresh source starts. SQLite may
legitimately change database/WAL/SHM bytes on reopening; the post-restart check
is logical data preservation. The adapter conservatively treats live, partially
created or unknown writers as potentially writing, independently of the paused
capture flag. Every attempted fresh cohort increments generation before create.

## Authored stores and limits

The real API initializes three stores. The fixed plan literally pins all three
current PRAGMA user_version values to 0: data/transcript-v2.db,
data/lexirise/exports-v2.db and data/lexirise/reading-cache-v2.db. Current table
column sets are checked separately. Zero is not evidence of a versioned schema
migration or compatibility with older/newer writable code. Unexpected SQLite
stores and changed versions are refused, not discovered and automatically
approved. Transcript initialization's real PRAGMA optimize may create the exact
optional SQLite statistics table sqlite_stat1(tbl,idx,stat); its columns are
checked, and other extra tables remain refused. Only the transcript contains
authored semantic records; empty export
and reading schemas do not prove learner-state/account continuity.

Chinese text, zh/zh-Hans source context, English translation, audio locale,
texts map and authored unvoiced status are preserved. No recording, game files,
model weights, account key or fake DPAPI credential is used. The selected test
game identifier is a fixture row identity, not real Hito/Migaku acceptance.

The existing copy helper selects data, host-settings and work/voice-assets.
This case places actual stores in data. It does not establish relocation of
source/settings.json, cache/work roots, external exports or credentials.
WAL/SHM presence is counted as observed; absence does not claim native retained
WAL coverage. Existing cheap migration tests retain their authored WAL cases.

## Failure and native invocation

Unknown creation/HTTP identity, failed strict drain, unsignaled retained writer,
poisoned handle or unconfirmed cleanup invalidates the adapter. The coordinator
remains alive with its leases/handles; failed event/receipt I/O cannot bypass
that hold. No generic Job drain, PID adoption, stale raw-handle retry or finally
lease release turns the failure into a pass. An external workflow timeout may
end that owner only as failed/unverified containment; keeper death stays open.

A deterministic copy/schema refusal after every writer has confirmed stopped
preserves both fixture trees and recovery checkpoint. It can explicitly close
the coordinator only after its closing writer validation passes. It cannot
automatically activate/resume the failed copy. Resume/recovery after native
copy interruption is a later experiment.

The build-host harness reuses the existing actual Enter-CompanionOperation
contender and native lease observer. Nine fixed checkpoints require both leases
and actual source entry blocked. Native blocked means exact sharing violation 32;
permissions, timeout and other outcomes are unavailable/failure. Sampled
contention supplements the continuous owner lifetime; polling alone is not a
continuous exclusion proof. Source entry is open only after explicit release.

This case starts its fixed owner with a local I/O wrapper, preserving the
isolated environment and existing host entrypoint. It does not inherit C1's
unbounded text-capture tasks. Stdout has one consumer and at most one pending
raw BaseStream read: a fixed 4096-byte buffer plus an 8192-byte line buffer.
The byte cap is enforced before strict UTF8 decoding; bounded leftover bytes
can serve the next phase. Overflow, missing LF/early EOF, invalid UTF8, deadline
or I/O error poisons that reader without rearming it. Stderr is discarded to
Stream.Null using a fixed 4096-byte asynchronous copy buffer, with no stored
content/string/hash/count. Reader/discard failure and failed receipt I/O keep
the live owner held; they cannot trigger kill, PID adoption or unknown disposal.

After the normal extracted candidate is prepared and verified, hosted Windows
invocation is:

```powershell
pwsh -NoProfile -File scripts/probe-frozen-data-copy.ps1 `
  -RuntimeRoot <extracted-runtime> -Provenance <candidate-json> `
  -Output output/checks/r19-frozen-data-copy.json
```

PowerShell is a build-host prerequisite, not part of the user runtime toolchain.
The integrated experiment runs a separate ten-minute step after the living
keeper cases, with an exact receipt allowlist. The external deadline is failed
containment of an experiment; it cannot prove coordinator-loss recovery.
Only the sanitized receipt may be uploaded: no control events, full migration
manifest, root/fixture identities, transcript rows, PIDs, raw logs or databases.
Passing metadata requires two source cohorts, four retained writer signals,
strict C2 twice, old-barrier refusal, source/copy/semantic/pointer checks, nine
actual source blocks, explicit release and private cleanup. It remains
r19_complete=false with production and target activation false.

Targeted checks are `backend/tests/test_runtime_data_copy_probe.py` plus existing
host/coordinator/migration regressions. Local doubles prove order and actual
SQLite semantics; they do not prove Win32 process ownership. Pure PowerShell
contracts are explicitly unavailable where pwsh is missing and must run in
hosted Windows. The checkpoint above verifies their actual Windows execution
and this fixed frozen case; later source changes need their own evidence.
