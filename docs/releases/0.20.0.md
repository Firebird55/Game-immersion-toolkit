# 0.20.0 — Automatic toolkit upgrades and reliable game preparation

## Fixes you will notice

- **Game updates no longer sit at a misleading 2%.** The status now comes from the language jobs that actually run. It identifies the game, language, current operation, queue, elapsed time and retry error. Extraction uses an indeterminate indicator instead of claiming an invented completion percentage.
- **Prepared languages repair themselves before you launch a game.** While the toolkit is open, every configured game language is checked at startup and every two minutes. Matching cache metadata no longer hides an empty or invalid table. Saved language choices can recover interrupted registration. Healthy tables are reused and replacements are validated before publication.
- **Language errors explain the next step.** Missing selections, active preparation, failed extraction and unavailable tables have distinct explanations. Choose a language once for a new game; missing game folders and voice packs still require setup in the game launcher.
- **Toolkit software now updates too.** Stable releases are checked on startup and every six hours. The updater downloads the distribution, verifies SHA-256 checksums and the source commit against the published tag, then prepares and activates the replacement. Setup → General & Updates shows the running version, download bytes, installation stage and retry controls. Automatic installation can be disabled there.
- **Account settings are hidden in Migaku mode.** Lexirise's local account and sentence destination now have a compact entry screen; study languages, dictionaries and remote preferences open separately. Account writes still require an explicit save.

## Installation and release improvements

- Existing installations need this upgrade once to gain the automatic updater. Copying newer source files alone does not replace an already-running runtime. Install using the distribution's `scripts/update-companion.ps1` with the existing installation as `-Root`.
- Updates preserve local transcripts, favorites, calibration, language choices, account keys and game files. A failed preparation retains the existing runtime. Dependency preparation has a bounded time limit and private logs.
- Publishing a release manually on GitHub now runs the same build, browser, packaging and extracted-distribution checks before uploading assets to that release. A manually created version tag also supplies the packaged version metadata. An existing release no longer makes the upload fail just because it already exists.
- The Checks and release workflow can also upload assets when manually run **on a version tag** with **publish** enabled. Running it on a branch remains candidate validation and does not publish.

## Included upstream improvements

This release also includes the changes since 0.19.2: remembered mobile setup and libraries, per-game automatic mobile exports, atomic replacement and recovery of interrupted exports, plus stronger CI source and artifact verification. Older local copies of these files are not restored over their newer upstream versions.

## Dependencies and verification

Compatible dependency updates are reviewed together. The native NumPy/SciPy/ONNX stack remains pinned pending a coordinated migration; TypeScript 7 and Node 26 types are not introduced into the current toolchain. Dependabot continues opening grouped weekly pull requests, with the full `required-checks` gate and an up-to-date branch required before merging.

The existing Python, JavaScript, browser and Windows suites remain the tests used by GitHub. Focused regressions cover damaged-table repair, saved selections, verified release extraction, offline failures and manual-release version metadata. Hosted release checks additionally validate the packaged artifact. Synthetic checks do not certify every installed game, native capture layout or physical phone.
