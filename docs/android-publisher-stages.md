# Reviewed Android publisher stages

`packaging/android/publisher-sources.json` is the explicit maintained-source
closure. It pins seventeen original toolkit modules from reviewed commits, by
SHA-256 after UTF-8 CRLF-to-LF normalization. The ordinary APK source manifest
separately binds every actually delivered Python source byte. The build refuses
a changed producer until its closure policy is reviewed. No downloaded provider
code or automatic dependency search is used.

Together with the 57 core/host/decoder, explicit crypto and authored acceptance modules, this
policy selects 74 owned modules. The shared `text_display` dependency
is required by `textmaps`. The six newest modules provide Wuthering's passive
bootstrap factory, original ELF/source/locale readers and shared APK/ZIP readers.
The additional NTE text-receipt reader uses only the existing protocol and private
path guards. It makes retained-source validation self-contained, without adding
the native authoring runtime or enabling Android text preparation.
The generated acceptance provider is installed
only by a separately named, explicitly opted-in native DEBUG startup; it never
changes the production registry or establishes publisher-content coverage.
The NTE and Reverse factories require only CPython's standard library.
One additional context-only module, `sophon_assets`, reads bounded checksummed
launcher manifests using the reviewed [Zstandard native cohort](android-zstandard.md).
It does not register another provider. The two factories still import only the
standard library on their Android stages; their later Windows source modules
are refused before import. The toolkit's own source license applies to these
owned modules; the Zstandard wheels retain their separate original notices. Original client artifacts acquired later are private input data, not
application libraries or shipped game code.

ZZZ remains excluded because its current bootstrap imports Android crypto and
compression implementations that have not been packaged and proved. Endfield's
current reviewed factory requires its Windows decoder/hash runtime before I/O.
Its new lazy writer seam does not remove that host gate. Genshin, Star Rail
and Infinity Nikki require their own reviewed complete factory
closures before inclusion. The packaged Capstone data decoder alone does not
establish any of these capabilities.

Tests must import this exact closed source namespace in an isolated process,
deny desktop/native helper imports and unaccounted network operations, then
exercise the real registry, service and context-owned transport against authored
publisher responses. A successful host fixture is source/behavior evidence;
Android stage execution still requires a new APK and an actual Android runtime
proof. The earlier 54-module decoder candidate remains a separate artifact.

The current 74-module composition has closed-namespace host validation only.
It has not produced a newly audited APK or a device acceptance result. The
73-module physical result below remains bound to its original source and APK.

The Wuthering source pin is `4f2be4ba`. Its optional explicit transport factory
receives the same context/allowed hosts and defaults to ordinary
`PublisherTransport`; no network function is replaced globally. Cold import and
an absent native capability are tested with desktop/Crypto imports and network
connections denied. Its valid native route uses the maintained
`FrameOcr.publisherCrypto()` capability. The APK audit now includes every
Chaquopy bootstrap-native ELF, including both mmap ABI extensions, alongside
the existing root/native-wheel audits and 16-KiB alignment requirements.

An explicitly requested DEBUG self-test uses a newly signed, approximately
2.3-kB authored APK and 14-KiB authored ELF. Only the fixture bytes are embedded;
fixture generation, desktop Crypto and test modules are not shipped. Both text
modes exercise the real service, byte budgets, APK signature/full-body integrity,
selected-member Deflate, mmap registration/output reader and stopped format
gate. Corrupt-carrier and cancellation cases retain an existing data marker.
A fresh service restores the completed stage without transport. The native
acceptance assertion additionally binds the actual JNI crypto proof and loaded
mmap extension hash to the audited candidate. Host fixtures passing these paths
do not establish Android/JNI execution, publisher HTTP or whole-game readiness.
The source-specific physical result below establishes this authored stage on one
Android target; it does not establish a prepared game.

## Physical authored bootstrap acceptance, November 18, 2026

Source `3029583d5ebd6f7982ac00df3d9b65bdef0ba49e` produced debug version 57,
115,390,204 bytes, SHA-256
`d49c9549dee1578fe8da2b828e5a5e1dc237b4547e6f71ffc6de4ec8826f881e`.
The complete 73-source namespace, policy, generated fixture, native notices,
signature and the then-enumerated 65 native ELF entries passed the candidate's
source-specific static audit.
The audit now includes the existing 24 Chaquopy bootstrap extensions; the nested
`java/chaquopy.so` bridge is explicitly admitted, while unexpected nested
libraries, missing mmap, wrong ABIs and insufficient alignment are rejected.
An auditor-only follow-up found 96 further native entries inside the two
standard-library IMY containers. The same machine/alignment parser separately
passed all 96 actual APK entries, making 161 inspected native members; this
supplement does not rewrite the older audit or runtime source identity.
The maintained auditor now centrally inventories root libraries, bootstrap
extensions and every requirements/stdlib IMY, including the four pure software
containers. Unknown containers, native code in a pure container, unexpected
native namespaces, missing TLS/SQLite modules, duplicates and wrong machine/page
alignment fail closed. This changes audit coverage without rebuilding a runtime.

That exact installed APK passed a normal version-56-to-57 update and two fresh
cold self-tests on a Redmi ARM64 device running API 36 with 4-KiB pages. No
uninstall, data clear, downgrade or owner signing-identity update was used.
The actual Python-to-Java cryptography capability authenticated the 2,309-byte
authored APK, and the actual bundled mmap extension read its 14,336-byte
authenticated ELF member. The loaded ARM64 mmap extension was 25,312 bytes,
SHA-256 `b33936b6761094939a3c32da9dbe8847b3520c0337163199f1311c8db5393977`,
matching the APK audit. Both request modes completed the expected native-source
stage. Corrupt full-carrier and cancelled-transfer cases were rejected, charged
their received bytes and preserved an existing authored data marker. Reopening
the real service reused the retained stage without transport and kept the
unresolved manifest-format gate.

Both cold runs also passed the existing 57 crypto cases, nine Zstandard cases,
data-decoder contract, native OCR-to-authored-caption/original-clip path,
MediaPlayer completion, four preview cases and Keystore tests. The earlier
protected blob reopened after the update and restart. The canonical shared-core
result remained `1039a44a7b63988cb8df1d11b0924027a8d3e7b40896bd9a4f20f712d0db92b0`.
Normal startup was restored after testing.

The transport supplied only authored responses: no original game assets or
official-server HTTPS were exercised, and device-wide egress was not blocked.
This is neither original-game preparation nor an ENTRY-key solution, text/audio
Ready result, 16-KiB runtime result or x86_64 execution proof. The static 16-KiB
checks and the separate older-source hosted emulator run retain their own scope.

The current reviewed baseline is source cohort `0624af55`; NTE's factory also
includes the reviewed voice-stage factory `3219971c` and its pure text-receipt reader
from `b9acf749`. All fourteen late-stage branches call the non-Windows reader gate
before importing their desktop-only dependencies. The isolated closed-source
fixture exercises every branch without those dependencies present. Updating a source pin does
not package the Windows managed reader, archive stages or their dependencies.
Original-audio receipt restoration also stops at an explicit Android capability
gate before importing its desktop reader or codecs. The closure remains 74
modules; this source revision has no new APK/device acceptance.
Sophon uses the same context-isolated source and byte-window fix as `8be26e32`.

These boundaries apply to both Text only and Text + audio. No text-only stage
may acquire optional voice banks, and a mixed bootstrap carrier must disclose
its full transport/storage cost before transfer. No new full-game, network or
Android stage execution acceptance follows from the 73-source package policy.
