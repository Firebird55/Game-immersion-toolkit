## Recorded observation

Preflight checks the existing Git visibility and source-attribute helpers before
claiming a clean HEAD. Assume-unchanged/skip-worktree flags and effective
filter/ident/working-tree-encoding attributes, including explicitly unset
attributes, make evidence unavailable. Nothing clears index flags or changes
configuration. This check reads Git metadata; it does not export a whole private
manifest or use Git blob bytes as the working-source observation.

A fresh private before snapshot records eligible actual working files under the
existing evidence root. Eligibility is tracked public backend Python source,
the finite build controls/configured hook, and these eight fixed script inputs:

- `scripts/__init__.py`;
- `scripts/build_agent_fingerprints.py`;

The relevant closed target mapping must remain exactly the reviewed mapping.
Observing another script does not admit it. Empty source files are valid and
remain distinct from absent files. The existing main and ASR Analysis objects
provide actual pure/script origins before PYZ construction. One path appearing
in multiple lists becomes one source record with the sorted union of actual
roles. Tracked but unused candidates do not become collected-source records.
Fixed build controls are explicitly declared inputs, not evidence every hook or
dynamic build import executed. The readiness script has a separate declared
resource role when verified through its existing resource hash.

Pinned PyInstaller 6.22.3 represents PEP-420 namespaces as `NamespacePackage`
nodes with `filename='-'`, `code is None`, and pure TOC kind `PYMODULE` (or its
optimization variant). They become zero-byte generated namespace markers, not
source files or builtins. Exclusion requires the actual Analysis graph's exact
pinned node type/identifier/filename relation. The report counts these as
`namespace_generated`; it publishes no namespace directory or arbitrary module
name. A wrong node, unknown sentinel, missing or project-cache-only origin
refuses the observation. Supplier origins are excluded only by the existing
verified installed-file map. Native ownership is a separate report.

## Public report and limits

The only new public filename is
`runtime-bundle/quarantine/RUNTIME-SOURCE-INPUTS.json`, schema
`proxy-r19-runtime-source-inputs-v1`. It records current source/build/profile,
actual input-manifest and private-baseline byte/hash identities, both Analysis
states, clean before/after states, sorted source records and selected-map
digests. Each record has only `path`, sorted finite `roles`, `raw` and
`canonical_lf`; byte identities have only `bytes` and SHA-256. Canonical LF is
strict UTF-8 with CRLF replaced by LF; NUL/bare CR are rejected. The two private
baseline/observation files are never uploaded. No paths outside the known
relative source set, environment values, license strings, source contents,
credentials, logs, databases, model payloads or native binaries are published.

Caps are 1,024 project records, 2 MiB per source file, 32 MiB unique source bytes
per snapshot, 20,000 TOC rows and 512 KiB public JSON. Repeated aliases do not
cause repeated content reads within the same Analysis. Root-first ordinary-file
checks precede descendant IO; file descriptor metadata is compared before and
after reading. The finalizer verifies original recorded identities against
actual final source bytes, the current clean HEAD and the unchanged input
manifest. It also binds that manifest identity to the native collection report.

The public status is `observed-not-approved`. Unsafe, unknown, incomplete or
changed evidence refuses the required gate; it is not silently omitted or
published as a partially trusted map. A close/flush/readback failure retains the
actual private stream/error. Publication closes a fresh private sibling before
exclusive commit and exact bounded readback. A stale destination is preserved.
The workflow performs another strict current-source/readback check and requires
its fixed validated marker before the explicit source report artifact path can
be uploaded. No wildcard or full private BUILD-INPUTS upload is added.

These are actual selected **origin files stable at observed boundaries**.
Analysis can obtain a compiled code object or use a cache before those TOCs are
available. Stable endpoint reads cannot exclude a change-and-restore race or
prove which bytecode was compiled. `compiled_code_identity` remains
`unverified`, supplier closure remains separate and OS/toolchain prerequisites
remain `unbound`. Generated code, frontend source-to-built-assets and complete
source/relinking closure are not established. Metadata never authorizes process
ownership, mutation, activation, copy or cleanup.

The focused tests use authored source files, actual pinned namespace node types
and TOC fixtures, with real filesystem failure/retention cases. They exercise
the actual source-required spec path for missing and unknown sources and a
known positive source map. They do not execute a native freezer or establish
Windows behavior. Existing native-only authored tests use an explicit
`source-map-not-tested` stand-in; their supplier/PE assertions remain separate.

All delivery/rights/runtime/production, global/physical writer, keeper-loss,
warm-routing, ordinary Windows 11/capture and complete R19 gates remain open.
No installer, release, live migration or PR #59 action is part of this change.
